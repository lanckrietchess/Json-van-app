# LC35 / hub 9.13.0: Creator Studio Content Hub, cloud export, Clip Archiver and variant remixer

Page: `index.html`, `sw.js`, `manifest.webmanifest` (built from 9.12.0 with `apply_patches_v35.py`, 5 exact-match hooks, module in `lc35-studio.js`).
Server: `server-lc35/arena.js` (adds 6 actions to the Arena function, includes everything from 9.10.0 to 9.12.0), `server-lc35/20261027100000_lc35_content_hub.sql`, `server-lc35/patch_arena_v35.py`.

## Deploy order
1. **SQL:** run `server-lc35/20261027100000_lc35_content_hub.sql`. Creates `arena.lc35_content` and, where Storage is installed, the **private** bucket `creator-content` (file size limit 50 MB, video types only). Idempotent.
2. **Check the bucket limit in the Supabase dashboard.** The free plan caps a file at 50 MB. A 60 s 1080p video can be 30-60 MB; 720p is about half. If you raise the plan limit, raise the bucket limit and `CONTENT_MAX_FILE_MB` together.
3. **Arena function:** back up, then deploy `server-lc35/arena.js`. It needs `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`; Supabase provides both to Edge Functions automatically. Optional secrets: `CONTENT_BUCKET` (creator-content), `CONTENT_MAX_ITEMS` (80 projects), `CONTENT_MAX_MB` (900 MB per library; the free plan has 1 GB for everything), `CONTENT_MAX_FILE_MB` (50), `CONTENT_URL_SECONDS` (86400).
4. **Who may use it:** the admin (admin secret) and players in the `creators` group, the same rule as the Creator Hub (admin mode > Creator hub > add a creator). The admin has one library on every device; each creator has one library per device.
5. Deploy the page files.
6. **Run one real upload before launch** (see the limits below): record a short take, press **Save this take to Content hub**, open the hub, post it, mark every platform green or red, press Trash.

## What it does
| Request | What it does now |
|---|---|
| 1. Content library + status dashboard | A **Content hub** button in the Studio stage row (and in the take editor) opens a full-screen library. Each project lists TikTok, Instagram, Facebook and YouTube with a status chip: **red = Skip** (do not post), **orange = To do**, **green = Posted**. A chip shows the colour and a word, and has an aria-label, so it never relies on colour alone. Press a chip to change it (orange, green, red, orange); it is saved in the cloud at once. Each platform has an "Open uploader" link. |
| 1. Trash / Archive | A prominent red button on every project. It stays **disabled** and says which platforms it is waiting for until none is orange. Then the first press arms it ("Press again to delete", disarms after 4 s) and the second deletes the cloud file and the project. The rule is enforced **on the server too**: a delete with an orange platform is refused (409), even from an out-of-date screen or another device. If the storage cannot delete the file, the project is kept (nothing is half-deleted). Unfinished uploads can always be cancelled and are swept away after an hour. |
| 2. Cloud export | Exports go to a private Supabase Storage bucket, not to the PC. The browser asks the Arena for a one-time signed upload URL and sends the file straight to storage (with a progress bar); the Arena then confirms the real size from storage. Where it saves: **Save this take to Content hub** (take editor) and **Render ... to Content hub** (project timeline). If the cloud is not available or the file is over the limit, the video is saved as a normal download instead, with a message; nothing is lost. |
| 2. Drag-and-drop | A **Drag to upload** handle on every project carries the video as a cloud file link. In desktop Chrome and Edge, dragging it onto the upload area of another page (TikTok Studio, Instagram, Facebook, YouTube Studio) in a second window, or onto the desktop, delivers the file. Also: **Copy link** (valid 24 h), **Download**, **Preview**, and **Share to app** (the phone's share sheet, which reaches TikTok and Instagram apps). Links are signed and expire; they are re-signed whenever the hub opens. |
| 3. Clip Archiver | In the take editor, a **Project timeline**: add your takes (Hook A, Hook B, Body, CTA TikTok, CTA Instagram...) as ordered clips with a role. The **Clip Archiver** switch shows an **Archive / Restore** button on every clip. An archived clip stays on the timeline (dimmed, struck through) but is skipped in every render. Nothing is deleted, and removing a clip from the timeline keeps the take. |
| 3. Variant remixer | **Save current clips as variant**: name it, give it a CTA label (for example "TikTok bio link" or "Instagram ManyChat") and tick the platforms it is for. Pressing a variant switches the clips on and off to match it. Variants remember their switches per take, so a clip you remove and add back keeps its old state. **Render this variant** and **Render all variants** join the active clips, each with its own cuts and captions, into one video per variant and send each to the Content hub: the platforms it targets start orange, the others red, and the CTA label and the clip list are stored with it. "Render all" puts the timeline back exactly as it was. |

## NOT tested, and what you must know
1. **Real Supabase Storage.** I tested against a mock that follows the documented endpoints (signed upload with a multipart PUT, signed download, HEAD, delete). If the real service answers differently, the first test upload will show it. Check especially that the browser can PUT to the signed URL from your domain (CORS) and that very large files finish (consider resumable uploads later).
2. **Dragging into TikTok, Instagram, Facebook or YouTube was not tested.** I verified the data the drag carries and that its URL serves the exact file. Whether a given platform's page accepts a drag from another window depends on that platform and your browser (desktop Chrome or Edge only; Firefox and Safari do not support the file-from-link drag). If a platform refuses, use Download, or Share to app on a phone.
3. **MP4 or WebM.** The recorder uses MP4 when the browser can (Chrome, Edge, Safari) and WebM otherwise. TikTok and Instagram can reject WebM. Settings > Format on "auto" is the right choice; check what a real export from your device produces.
4. **Space.** 1 GB of Storage on the free plan is about 20 to 30 finished shorts. That is exactly what Trash / Archive is for. A project with an orange platform cannot be deleted, so keep the statuses up to date.
5. **Platform upload links** (the "Open uploader" buttons) point at each site's main upload page. Platforms move these; they are one line in `lc35-studio.js` (`PL`).
6. **Rendering is real-time.** A 40 s variant takes about 40 s to render and the tab must stay open. "Render all variants" is that times the number of variants. Recording quality (Settings > resolution) is the lever for file size.
7. **Library scope.** Creators (not the admin) have one library per device, because their Creator Hub access is tied to the device. The timeline and variants are stored on the device (like takes), not in the cloud; only exported videos and their status are in the cloud.
8. **The Takes panel is small by default.** The timeline sits at the bottom of the take editor; make the panel larger or use the Layouts menu.
9. A signed link is a bearer link: anyone who has it can watch the video for 24 hours. The bucket itself is private.
